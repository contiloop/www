# 0011 Type rules live in the plugin, one file per document type

Context: the author wanted the rules for each kind of document kept in the repository, beside the skill that applies them, where a development session can read, edit and release them. Decision 0003 put accepted rules in `~/.claude/www/writing-rules.md` and decision 0010 put lessons in `~/.claude/www/cases/`; both held the author's rules on one machine, outside the repository, where no release carried them and no session on the repository saw them, and the Codex sandbox refused both writes by default.

Decision: one numbered rules file per document type under `references/types/` (`presentation-script.md`, `research-paper.md`, `report.md`, `essay.md`; `other` has no file), shipped with the plugin, read with `references/writing-rules.md` whenever the record's type line names the type and winning over it on conflict, because it is the narrower file. A rule the author accepts while writing is recorded in that document's part 4, where the document's checks read it, and shown in general words as the line to add to `writing-rules.md` or the type file. Nothing is written outside the document folder: the skill writes `design.md` and `draft.md` only. Adding a rule to the plugin is a repository edit: append the line, raise the three manifest versions, rebuild, reinstall.

Alternatives: the user rules file and the case store of 0.3.0 (kept outside the plugin and written at run time, so the rules lived where the repository could not see them and a reinstall on another machine lost them); a link from the home folder into the repository, as the case store had (a per-machine step the install does not make, and a write at run time into a committed folder); a configurable path for the rules (one more thing to set on each machine, and the skill still writing outside the document folder).

Consequences: the skill writes two files, so Codex's default sandbox suffices; a new rule guards the document whose record holds it at once and other documents only after a release; the author adds rules on request in a development session, which is where the type files fill up; the acceptance fixture needs no store moved aside; `references/cases.md`, rule 35 and the end-of-document case offer are gone, and the rule count is 34. Supersedes 0003 and 0010.
