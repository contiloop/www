# 0010 Case memory: one file per finished document, read for how to write

Context: what one document taught (which first-draft problems the author corrected, what the author said, what the revision did) was lost when the next document started in another folder. The user rules file holds only general rules that passed rule 30 and were accepted under rule 33; a lesson tied to a kind of document, a reader or a kind of material does not pass rule 30 and so was kept nowhere.

Decision: a case store at `~/.claude/www/cases/`, one Markdown file per document folder named `<date>-<folder name>.md`, keyed by the folder's absolute path and rewritten whole when the document is finished again. The case has fixed parts (task type from a fixed set beside the record's own type line, task context, materials, first-draft problems, author feedback verbatim with understanding remarks included, revisions made, lessons with the author's and the skill's kept apart). It is offered once per session when every unskipped section is drafted and nothing is open, also written on request, shown whole and written only on the author's word. It is apart from the two rules files. Cases are read when the record holds type and reader and again before a section is drafted, revised or checked, matched on task type then purpose, reader and material, and named in one line; they shape how the skill writes, never what the document argues: nothing from a case enters the record, a proposal or a draft, and a case may raise a question but never supply the answer. Rule 35 states this in the shipped rules file.

Alternatives: a case file in the document folder (lost to the next document, which is in another folder, and a fifth file the author did not ask for beside the manuscript); one `cases.md` holding every case (one file to rewrite whole on every document, and no key per document); writing the case unasked (a write outside the document folder the author did not see); a case per completion instead of per document (several files for one document, with the old lessons kept beside the corrected ones); a case as a fourth style source in `references/drafting.md` (a style source is tested sentence by sentence, while a case is read for how a document of that kind was written and must never supply a line).

Consequences: a fourth run-time write path, and the Codex sandbox refusal now covers two paths outside the document folder; the acceptance fixture is run with the store moved aside, since the draft would otherwise depend on the machine's cases; promotion of a lesson to a general rule still goes through rules 30 and 33, proposed when the case is written if the wording passes rule 30 and at reuse when a lesson stands in two or more matching cases; a new reference `references/cases.md` and new vocabulary (case, content remark, understanding remark, the task-type set).
